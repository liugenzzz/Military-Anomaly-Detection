# 描述任务设计（v0.4 方案，待确认后再改代码）

## 一、调研结论：抄哪些、为什么

### 主要参考：`liugenzzz/target_detection_vl_dataset/qwen3vl_sft_builder`

这套目标检测 SFT 构建器里，最值得抄的是它对「描述」的处理。它把描述拆成 **7 个子类型**
（appearance / state / part / position / relation / contrast / full），每个子类型的答案
**信息结构完全不同，不是换说法**。README 里那句话点破了关键：

> **`must-not` 是七种能不能立住的关键。** 模型很容易把「只说外观」写成「位于画面左侧的
> 一辆红色三轮车」—— 加了方位就又滑回三段式。没有这道闸，七种跑几轮会退化成同一种。

具体要抄的机制：

| 机制 | 作用 |
|---|---|
| **`must-not` 禁用词** | 答案里出现就整条丢。**这是防模板化的唯一硬手段**，其余都是软约束 |
| **`needs` 前置条件** | 写进提示词，让模型自己判断这张图能不能出这类题 |
| **`answer-spec`** | 明确写答案该装什么、至少几项 |
| **「说不出就返回空，不要编」** | 抗幻觉，比事后 review 更省 |
| **`q-example` / `a-example`** | few-shot，比纯描述性指令有效得多 |
| **问法 bank（15–20 条/任务）** | 治问句死板。配 `#! forbid` 防止问句跑偏 |
| **`full` 三段式压到 20%** | 综合描述本身没错，但不该占满 |
| **review 五维打分** | correct / grounded / clear / instruction / **needs_image** |
| **难度分级 + 尺寸拒绝** | `size_reject_px: 16`，太小的目标直接不出题 |
| **温度分两档** | 生成答案 0.35（求准），选择/多样化 0.85（求变） |

其中 **`needs_image` 这一维最值得单独说**：检查「把图遮住只看文字，凭常识能不能答对」。
街景图上问「有没有潜水艇」，不看图也知道没有——这种样本训不出任何东西。
我们的否定题最容易踩这个坑，必须靠它筛掉。

### 其他参考

- **VRSBench**：GPT-4V 生成 + **人工逐条校验** 29,614 条详细描述。人工校验我们做不到，
  用「换模型 review」替代
- **CUVA**：异常因果的 **what / why / how 三段式**人工标注，这个结构直接可借鉴到推理题
- **对抗模板坍缩的研究结论**：LVLM 有语言先验，天然偏好「从中心到周边、从概括到细节」
  的固定叙述顺序。破解办法正是**在提示词里指定只写某一个随机侧面**，强迫它偏离默认套路。
  这印证了上面的 must-not 方案

## 二、主线结构：你说的「两点」就是主线

> 「总的是两点：问有什么异常行为 → 回答爆炸等 → 然后描述方位」

这正好是一条**三轮主线对话**，参考项目的 `inventory_locate` 也是这个结构：

```
轮1  Q: <image>这张航拍画面中是否存在异常？是什么类型的异常？
     A: 存在异常，为爆炸/火光。

轮2  Q: 该异常出现在画面的什么位置？
     A: 火光区域位于 [421,388,533,502]，处在画面中部偏右。

轮3  Q: 请描述该处火光的亮度特征与伴生现象。        ← 这一轮按侧面随机抽
     A: 火焰呈明亮橙红色，与周边深色地表形成强反差，核心区域近乎白色，
        其上方伴随灰褐色烟尘向东北扩散，火点边缘可见零星飞散物。
```

**一条主线样本 = 3 条 QA**（判定 1 + 定位 1 + 描述 1）。建议判定与定位的配额中
**50% 以主线形式产出、50% 以单轮形式产出**——单轮保证模型能独立响应单个指令，
主线保证它能在对话里连贯地追问下去。

## 三、四类异常各用各的描述侧面（核心设计）

每类异常 **7 个描述侧面**，其中 3 个是共有骨架、4 个是该类专属。**专属侧面完全不同**，
从根上避免四类都写成「位于 X 的 Y，周围有 Z」。

### 共有的 3 个侧面

| 侧面 | 答案装什么 | must-not |
|---|---|---|
| `evidence` 判定依据 | 凭哪些视觉线索判定为这类异常，至少三项 | 位于 画面 方位 左侧 右侧 上方 下方 |
| `position` 空间方位 | 只说异常区域在画面哪一块、靠近哪条边、占多大幅面 | 颜色 形态 数量 因为 依据 |
| `full` 综合 | 三段式：是什么 + 在哪 + 什么特征 | — （**只占 10%**） |

### 异常聚集 `massing` —— 专属侧面侧重「构型」

| 侧面 | 答案装什么 | must-not | 前置条件 |
|---|---|---|---|
| `formation` 排列形态 | 几列几排、间距是否均匀、朝向是否一致、是否呈规则阵列 | 颜色 烟 火 | 目标数 ≥ 阈值 |
| `composition` 目标构成 | 都是什么目标、军用还是民用、有无混编 | 位于 画面 方位 | 有 ≥2 种类别 |
| `scale` 规模量化 | 数量、占据面积占画幅比例、密集程度 | 颜色 朝向 | 有 cluster_bbox |
| `site` 场地环境 | 所处场地类型：停机坪 / 开阔地 / 港口 / 道路 / 场站 | 数量 排列 | 场地可辨 |

### 爆炸/火光 `explosion` —— 专属侧面侧重「瞬时特征」

| 侧面 | 答案装什么 | must-not | 前置条件 |
|---|---|---|---|
| `intensity` 亮度形态 | 火球 / 闪光 / 明火，亮度与周边的反差，核心与边缘的颜色层次 | 位于 画面 方位 数量 | 火区可见 |
| `debris` 伴生现象 | 扬尘、碎片飞散、伴生烟、地表灼痕 | 位于 方位 | 有伴生特征 |
| `extent` 波及范围 | 影响面积、与周边目标的距离、是否波及建筑或车辆 | 颜色 亮度 | 周边有参照物 |
| `stage` 燃烧阶段 | 初燃 / 盛燃 / 余烬，**判不出必须明说判不出** | 位于 方位 | 恒可出 |

### 烟雾 `smoke` —— 专属侧面侧重「形态与走向」

| 侧面 | 答案装什么 | must-not | 前置条件 |
|---|---|---|---|
| `morphology` 烟柱形态 | 柱状 / 团状 / 带状 / 弥散，浓密程度，边缘是否清晰 | 位于 方位 火 爆炸 | 烟区可见 |
| `color` 颜色 | 灰白 / 黑褐 / 黄，颜色暗示的燃烧物性质 | 位于 方位 数量 | 颜色可辨 |
| `drift` 扩散走向 | 向哪个方位飘散、扩散幅度、是否受风影响 | 颜色 浓密 | 有方向性 |
| `occlusion` 遮蔽程度 | 遮住了多大范围的地表、是否影响对下方目标的观察 | 颜色 形态 | 有遮蔽 |

### 越界移动 `border_crossing` —— 专属侧面侧重「时序与相对关系」

| 侧面 | 答案装什么 | must-not | 前置条件 |
|---|---|---|---|
| `trajectory` 运动轨迹 | 从哪来、到哪去、运动方向、是否持续同向 | 颜色 数量 烟 | 有轨迹 |
| `timing` 跨越时机 | 在第几帧之间越过边界、越界前后的位置变化 | 颜色 外观 | 多帧序列 |
| `boundary_relation` 边界关系 | 当前在界内还是界外、距边界多远、由内向外还是由外向内 | 颜色 外观 | 有 region |
| `group` 群体特征 | 单个还是成组、是否同步移动、间距是否保持 | 颜色 位于 | 越界目标 ≥2 |

**跨类互斥词表**（额外加的一条，参考项目里没有）：烟雾类描述不得出现「爆炸/火球/爆燃」，
聚集类不得出现「烟/火」，越界类不得出现「集结/爆炸」。防止四类描述串味。

## 四、数量分配（描述提到 60%）

每个异常类 25,000 条：

| 任务 | 占比 | 条数 | 生成方式 |
|---|---|---|---|
| 判定 | 15% | 3,750 | 规则 |
| 定位 | 12% | 3,000 | 规则 |
| 计数 | 5% | 1,250 | 规则 |
| **描述** | **60%** | **15,000** | **LLM** |
| 推理 | 8% | 2,000 | LLM |

描述的 15,000 条分到 7 个侧面：

| 侧面 | 占比 | 条数 |
|---|---|---|
| `evidence` 判定依据 | 20% | 3,000 |
| `position` 空间方位 | 18% | 2,700 |
| 专属侧面 ① | 15% | 2,250 |
| 专属侧面 ② | 15% | 2,250 |
| 专属侧面 ③ | 12% | 1,800 |
| 专属侧面 ④ | 10% | 1,500 |
| `full` 综合 | 10% | 1,500 |

**正常类 43,000 条**的描述侧面只有 4 个：

| 侧面 | 条数 | 说明 |
|---|---|---|
| `hard_neg` 困难负样本辨析 | 8,000 | **最重要**：像但不是，差在哪。「14 辆车密集停放，但均为民用车辆，无军事装备」 |
| `scan` 常态巡查 | 7,000 | 画面里有什么，为何判定正常 |
| `position` 主要目标方位 | 5,000 | |
| `full` 综合 | 3,000 | |

**总量**：异常 100,000 + 正常 43,000 = **143,000 条**。
规则侧 4 类 × 8,000 + 正常 30,100 = 62,100；LLM 侧 80,900。

## 五、生成流程：你说的「先拿关键，再拿大模型优化骨架」

```
① 规则抽 FACTS          derive_events 的事件 + 目标清单 + 坐标 + 边界关系
                        零幻觉，这是所有答案的事实底座
        ↓
② 按侧面派题            每张图随机抽 1–2 个该类异常的侧面(按配比加权)
                        检查 needs 前置条件, 不满足就跳过这个侧面
        ↓
③ VLM 生成答案          输入: 图 + FACTS + 该侧面的 answer-spec/must-not/示例
                        temperature 0.35
        ↓
④ must-not 硬过滤       答案里出现禁用词 -> 整条丢, 不做修补
                        这一步是规则, 不花钱, 放在 review 之前省算力
        ↓
⑤ 换模型 review         五维打分: correct/grounded/clear/instruction/needs_image
                        任一维 < 3 丢弃
        ↓
⑥ 落盘 ShareGPT
```

**④ 放在 ⑤ 之前**是有意的：must-not 是纯字符串检查，零成本，先把明显跑偏的滤掉，
再花算力做 review。

## 六、待你确认的三个点

1. **配比**：描述 60% / 判定 15% / 定位 12% / 推理 8% / 计数 5% —— 计数压到 5% 是因为
   它与「异常检测 + 描述」的目标关联最弱，但保留是因为它是零幻觉真值。要不要再调？

2. **主线占比**：判定与定位各有 50% 打包进三轮主线、50% 单轮出现。主线多了模型更会对话，
   单轮多了模型更会执行单条指令。这个五五开合不合适？

3. **专属侧面**：每类 4 个专属侧面（共 16 个）是我按各类异常的视觉特点定的。
   有没有哪个不该要，或者漏了该有的？比如聚集类要不要加一个「与周边设施的关系」
   （停机坪旁的机堡、掩体）？
