# 异常类型定稿（决策记录 v0.2）

**每类目标 25,000 条 QA。** 按当前生成器每图产出 9–10 条 QA 计，即 **约 2,800 张图/类**。

## 定稿：4 类异常 + 正常

| ID | 类别 | 子类型 | 判定口径 | 目标 QA |
|---|---|---|---|---|
| `massing` | **异常聚集** | `personnel` 人员聚集 | ≥20 人密集成簇，**不要求军事身份** | 25,000 |
| | | `equipment` 装备集结 | ≥8 目标密集成簇 **且含军事目标** | （与上合计 25,000） |
| `explosion` | **爆炸/火光** | — | 帧级标签迁移 | 25,000 |
| `smoke` | **烟雾** | — | 帧级标签迁移 + bbox | 25,000 |
| `border_crossing` | **越界移动** | — | 轨迹跨越虚拟边界，位移过滤抖动 | 25,000 |
| `normal` | **正常** | 含 `hard_negative` 标记 | 无事件 | ≥ 总量 30%（约 43,000） |

**总计约 14.3 万条 QA，约需 1.3 万张图。**

之前估算筛选后可得约 3.5 万张可用图，现在只需 1.3 万——**富余的额度应该拿去提高筛选严格度换质量，而不是硬凑数量**。

## 为什么合并「集结」与「人员聚集」，但保留子标签

合并的理由是数据富余：两者可得图合计约 9,800 张（DroneCrowd 3,000 + ERA parade 1,000 + MAR20 3,800 + Mendeley tank 2,000），而一个类只需 2,800 张。

保留 `subtype` 的理由：训练时是一类（模型只需判断"有异常聚集"），但**评测时能分开看人员与装备各自的准确率**。零额外成本，信息不丢。

## 为什么军事目标约束只作用于装备，不作用于人员

这是本次最重要的一条口径。

**装备必须含军事目标。** DOTA 里满足「≥8 车辆密集成簇」的图绝大多数是民用停车场与物流卡车场。按纯数量+密度判定，它们会被大量标成"兵力集结"，训出来的模型会把商场停车场报成装甲集群。这种错误靠调阈值救不回来，因为标签本身错了。

**人员不设军事身份要求**，两个原因：

1. **技术上不可实现**：航拍与卫星视角下无法分辨军装与便装。坦克与轿车的俯视轮廓差异巨大，人穿什么衣服则完全看不出。要求"必须是军人"等于要求模型做它物理上做不到的判断。
2. **业务上也不需要**：真实值班场景里，禁区周边突然聚集 200 人，无论穿什么都该上报。系统应当报告**事实**（某区域出现大规模人员聚集）而非替人下军事结论。

同样的道理，类别名用「异常聚集」而非「兵力集结」——中性表述，不预设军事性质。

## 困难负样本：错标风险反而变成了资产

`require_any` 未命中时不是简单丢弃，而是把该图标为 `meta.hard_negative = true`，进入正常样本池。

**这些"规模达标但不含军事目标"的图，正是模型最需要学会区分的**：14 辆车整齐停在开阔地——是停车场还是装甲集结？唯一的区别是目标类型。有了这批样本，模型学到的是"看目标是什么"，而不是"看有没有一堆东西挤在一起"。

于是 DOTA 的角色发生了转变：从「集结数据来源」变成**「最好的困难负样本来源」**，实际价值更高。

已实测的五个用例：

| 输入 | 派生结果 |
|---|---|
| 14 辆民用车密集成簇 | 无事件，`hard_negative = true` ✅ |
| 12 辆车 + 1 辆坦克 | `massing/equipment` ✅ |
| 10 架飞机停机坪列队 | `massing/equipment` ✅ |
| 30 人密集聚集 | `massing/personnel` ✅ |
| 3 辆车稀疏分布 | 无事件，普通正常 ✅ |

## 停用的四类，以及为什么

停用的类别保留在 `configs/ontology.yaml` 末尾并标 `enabled: false`，恢复只需改一行。但恢复前请先确认数据量能撑到 2,800 张图。

### `fortification` 阵地/工事构筑 —— 四个层面都不成立

1. **数据差 9 倍**：ERA `constructing` 约 100 段视频，抽帧去重后约 300 张可用图，目标是 2,800 张。
2. **公开数据里几乎没有军事工事影像**：民用工地（挖掘机、塔吊、土方）遥感数据里有，但**掩体、壕沟、火炮阵地、伪装网在公开数据集里基本为零**。这不是筛选能解决的，是根本没有。
3. **判定本质需要多时相对比**：工事构筑的核心特征是"这里原来没有，现在有了"。单张图看到一片土方，分不清是新挖的战壕还是修路工地。而 DOTA / FAIR1M / VisDrone 全是单时相，没有同一地点的配对影像。
4. **只能靠合成，但泛化无法验证**：ARMA3 有现成的壕沟/掩体/沙袋资产可批量渲染，但这一类会 100% 是合成数据——**没有真实的军事工事图可用于测试**，等于做完了也不知道行不行。

**当前处理（方案 A）**：不作为独立异常类，但在**描述题**里保留这个概念——画面中有工程机械或土方作业时，让模型在描述中提到"可见工程作业痕迹"，不下"工事构筑"的判定结论。零成本，保留信息，不引入错标。

**唯一能做出真实效果的路径（方案 C）**：有真实军事工事影像（哪怕几百张）作为种子，配合 ARMA3 合成扩充，混训。没有种子数据就不要做。

### `convoy` 车队机动
与正常道路交通无法可靠区分，概念边界不清晰。车辆的运动状态已作为目标的 `moving` 属性保留，需要时可在描述题里体现。

### `naval_massing` 舰船集结
DOTA / FAIR1M 的 `ship` 绝大多数是民用港口，错标风险与民用停车场同理。军用舰船集结已并入 `massing/equipment` 的 `require_any`（`warship`）。

### `air_activity` 航空活动异常
与 `massing/equipment` 完全重叠——机群集结已被后者覆盖，单列一类只会互相抢数据。

## 各类数据来源与缺口

| 类别 | 需 2,800 图 | 实际可得 | 状态 |
|---|---|---|---|
| `smoke` | 2,800 | FASDD_UAV 约 8,000+ 含烟图 | ✅ 富余 |
| `massing/personnel` | — | DroneCrowd 抽 3,000 + ERA parade/protest/concert 约 1,000 | ✅ |
| `massing/equipment` | — | MAR20 3,800（机群）+ Mendeley tank 子集约 2,000 | ✅ |
| `explosion` | 2,800 | XD-Violence Explosion + UCF-Crime Explosion/Arson + ERA fire | ⚠️ 需密集抽帧，务必做近重复去除 |
| `border_crossing` | 2,800 | VisDrone MOT 约 56 序列 × 30–50 关键帧 | ⚠️ 需人工画约 56 条虚拟边界（约 1 小时） |
| `normal` | 4,300+ | DOTA 民用聚集（困难负样本）+ VisDrone + ERA non-event + Drone-Anomaly 正常段 + 异常视频正常段 | ✅ 充裕 |

**两个需要额外投入的点：**

- **`explosion` 数据偏紧**。爆炸持续时间短，需要在异常段密集抽帧（1–2 fps）才能凑够量，但这会产生大量近重复帧，`screen.py` 的闸 3 必须开着跑。
- **`border_crossing` 需要人工画边界**，这是全流程唯一的人工环节。但很快：一个视频序列画一条折线，56 个序列一小时能画完，且一条边界能派生出多个越界事件。
